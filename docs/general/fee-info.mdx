## Background

This doc describes functionality in Skip Go for accessing standardized information about the various fees that a user can incur while swapping or transferring. Common fees include:

* Affiliate fees (e.g. fees you charge the user for swapping on your frontend)
* Bridge and relayer fees
* Smart Relayer fees
* Gas fees

### How Bridging Fees Are Applied
Each fee in `estimated_fees` has a `fee_behavior` that tells you how it is charged:

*   **`FEE_BEHAVIOR_DEDUCTED`**: The fee is taken out of the transferred amount, so the user receives less on the destination chain. This is the case for most fees, including transfers from Cosmos chains and many transfers from EVM chains (e.g. CCTP, Go Fast, Stargate).

*   **`FEE_BEHAVIOR_ADDITIONAL`**: The fee is charged on top of the transferred amount, usually in the source chain's native token (e.g. ETH for Axelar and LayerZero transfers from EVM chains). Make sure the user has enough balance to cover both the amount and the fee.

## Understanding incurred fees from all sources: `estimated_fees`

`estimated_fees` in the response of `/route` and `/msgs_direct` provides a `Fee` array where each entry gives information about a particular fee.

Each `Fee` object in the array will have the following attributes:

* `fee_type`: Enum giving the kind of fee — `SMART_RELAY` or `BRIDGE`
* `bridge_id` : The ID of the bridge charging the fee (`BRIDGE`), or the bridge where Smart Relay is providing a service (`SMART_RELAY`)
* `amount` : The amount of the fee (expressed in the token the fee will be charged in)
* `usd_amount`: Estimated USD value of the fee
* `origin_asset` : An `Asset` object containing useful metadata for displaying and identifying the token in which the fee is denominated (its `denom` field gives the fee token's denom)
* `chain_id` : Chain ID where the fee will be collected
* `fee_behavior` : How the fee is charged — `FEE_BEHAVIOR_DEDUCTED` (deducted from the transferred amount) or `FEE_BEHAVIOR_ADDITIONAL` (charged on top of the transferred amount, e.g. a fee paid in the native token on an EVM source chain). See [How Bridging Fees Are Applied](#how-bridging-fees-are-applied)
* `tx_index`: The zero-indexed identifier of the transaction where the user will incur this fee (For multi-transaction routes, fees may be incurred after the first transaction)
* `operation_index`: The zero-indexed entry in the operations array where the user will incur this fee

 <Warning>
 **Included Fees & Current Limitations**

 The `estimated_fees` array consolidates certain fees for easier display. Currently, it includes:
 * `FeeType: SMART_RELAY` for `CCTP`, `CCTP_V2`, and `EUREKA` transfers.
 * `FeeType: BRIDGE` fees for the following bridges: `AXELAR`, `GO_FAST`, `LAYER_ZERO`, `STARGATE`, and `CCTP_V2` (Circle's fast transfer fee, when `fast_transfer` is set to `true`).

 Please note that fees for other bridges (e.g. `IBC`) and other costs like swap fees or gas are not yet included here and the steps where these fees occur are detailed in the `operations` array. We plan to expand the coverage of `estimated_fees` in the future.
 </Warning>
