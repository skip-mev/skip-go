## Routes

### `defaultRoute`

Sets the route shown when the widget loads, and requests a route on render. Find supported assets with the [/assets](/api-reference/prod/fungible/get-v2fungibleassets) endpoint.

```ts
defaultRoute?: {
  amountIn?: number;
  amountOut?: number;
  srcChainId?: string;
  srcAssetDenom?: string;
  destChainId?: string;
  destAssetDenom?: string;
  srcLocked?: boolean;
  destLocked?: boolean;
};
```

- `amountIn`: Preset input amount. If both `amountIn` and `amountOut` are set, only `amountIn` is used.
- `amountOut`: Preset output amount.
- `srcChainId`, `srcAssetDenom`: Source chain ID and asset denom.
- `destChainId`, `destAssetDenom`: Destination chain ID and asset denom.
- `srcLocked`, `destLocked`: Prevent the user from changing the source or destination asset. Either one also disables the button that swaps source and destination.

### `routeConfig`

Sets which routes the widget can use. Fields you don't set keep their defaults.

```ts
routeConfig?: {
  experimentalFeatures?: string[];
  allowMultiTx?: boolean;
  allowUnsafe?: boolean;
  bridges?: ('IBC' | 'AXELAR' | 'CCTP' | 'CCTP_V2' | 'HYPERLANE' | 'OPINIT' | 'GO_FAST' | 'STARGATE' | 'LAYER_ZERO' | 'EUREKA')[];
  swapVenues?: {
    name: string;
    chainId: string;
  }[];
  goFast?: boolean;
  smartSwapOptions?: SmartSwapOptions;
  timeoutSeconds?: string;
};
```

| Field | Description | Default |
|---|---|---|
| `experimentalFeatures` | [Experimental features](/advanced-transfer/experimental-features) to enable | `["stargate", "eureka", "layer_zero"]` |
| `allowMultiTx` | Allow routes that need more than one transaction | `true` |
| `allowUnsafe` | Allow routes with high price impact or poor execution. [More info](/advanced-swapping/allow_unsafe-preventing-handling-bad-execution) | `true` |
| `bridges` | Only use these bridges | All bridges |
| `swapVenues` | Only use these swap venues | All venues |
| `goFast` | Use [Go Fast](/advanced-transfer/go-fast) when available | `true` |
| `smartSwapOptions` | Advanced swapping, such as EVM swaps and split routes. [More info](/advanced-swapping/smart-swap-options) | `{ splitRoutes: true, evmSwaps: true }` |
| `timeoutSeconds` | IBC transfer timeout, in seconds | API default (5 minutes for routes that start on Cosmos) |

### `settings`

Sets defaults for settings the user can change.

```ts
settings?: {
  slippage?: number;
  useUnlimitedApproval?: boolean;
};
```

- `slippage`: Default slippage percentage (0-100) for Cosmos SDK chain swaps. Default: `1`.
- `useUnlimitedApproval`: Set the EVM allowance to the maximum amount when an approval is required. Default: `false`.

### `batchSignTxs`

Whether all transactions in a multi-transaction route are signed upfront or one at a time.

```ts
batchSignTxs?: boolean;
```

- **Default:** `true`
- When `true`, the widget asks the user to sign every transaction at the start, then broadcasts them one by one in order.
- When `false`, the widget asks for each signature just before broadcasting that transaction.

For example, for a route from Solana to Noble to Cosmos with three transactions, `true` asks for all three signatures upfront, then broadcasts Solana, Noble, and Cosmos in order.

<Note>
**EVM transaction limitation:** If an EVM transaction is the second or a later transaction in a route, it can't be signed upfront. That transaction and every transaction after it are signed one at a time when they are ready to run.
</Note>

### `simulate`

Whether the widget simulates transactions before executing the route, to check gas and balances.

```ts
simulate?: boolean;
```

- **Default:** `true`

## Assets

### `filter`

Chains and assets to show. Keys are chain IDs. A value of `undefined` allows every asset on that chain, and an array allows only those denoms.

```ts
filter?: {
  source?: Record<string, string[] | undefined>;
  destination?: Record<string, string[] | undefined>;
};
```

Example:

```ts
{
  source: {
    // any asset on this chain
    'noble-1': undefined,
  },
  destination: {
    // only these assets on this chain
    'cosmoshub-4': ['uatom', 'ibc/2181AAB0218EAC24BC9F86BD1364FBBFA3E6E3FCC25E88E3E68C15DC6E752D86'],
    'agoric-3': ['ibc/FE98AAD68F02F03565E9FA39A5E627946699B2B07115889ED812D8BA639576A9'],
    // any asset on this chain
    'osmosis-1': undefined,
  }
}
```

### `filterOut`

Chains and assets to hide. Uses the same format as [`filter`](#filter): `undefined` hides every asset on the chain, and an array hides only those denoms.

```ts
filterOut?: {
  source?: Record<string, string[] | undefined>;
  destination?: Record<string, string[] | undefined>;
};
```

Example:

```ts
{
  source: {
    // every asset on this chain
    'noble-1': undefined,
  },
  destination: {
    // only these assets on this chain
    'cosmoshub-4': ['uatom', 'ibc/2181AAB0218EAC24BC9F86BD1364FBBFA3E6E3FCC25E88E3E68C15DC6E752D86'],
  }
}
```

### `filterOutUnlessUserHasBalance`

Like [`filterOut`](#filterout), but a chain or asset stays visible if the user holds a balance of it.

```ts
filterOutUnlessUserHasBalance?: {
  source?: Record<string, string[] | undefined>;
  destination?: Record<string, string[] | undefined>;
};
```

### `assetSymbolsSortedToTop`

Orders assets by recommended symbol, in the order listed, when their pinning, search match, and balance priority are equal. To pin an asset above search matches and balances, use [`assetAnnotations`](#assetannotations) with `selector.pinToTop`.

```ts
assetSymbolsSortedToTop?: string[];
```

### `assetAnnotations`

Adds a badge, description, highlight, or pin to an asset, keyed by recommended symbol.

```ts
assetAnnotations?: Record<string, {
  variant?: "info" | "warning" | "error";
  swapPage?: {
    label: string;
  };
  selector?: {
    description?: string;
    pinToTop?: boolean;
  };
}>;
```

- `variant`: Color of the badge, description, and highlight. `info` uses the brand color. `warning` and `error` use the theme's warning and error colors. Default: `info`.
- `swapPage.label`: Badge on the swap page, on both source and destination rows.
- `selector.description`: Detail line under the asset name in the token selector.
- `selector.pinToTop`: Pins the asset to the very top of the token selector, above balances and search matches.

Example:

```ts
assetAnnotations={{
  "USDC.n": {
    variant: "info",
    swapPage: { label: "Migration required" },
    selector: {
      description: "Convert to USDC before support ends",
      pinToTop: true,
    },
  },
}}
```

### `hideAssetsUnlessWalletTypeConnected`

Hides assets whose wallet type isn't connected. Currently only Sei Cosmos and Sei EVM assets are supported. Added in v3.7.3. Default: `false`.

## Appearance

### `theme`

Customizes colors and corner radius. Pass `"light"` or `"dark"` to use a built-in theme, or an object to override parts of the default dark theme. Fields you don't set keep their default values.

```tsx
theme?: "light" | "dark" | {
  brandColor: string;
  borderRadius?: {
    main?: string | number;
    selectionButton?: string | number;
    ghostButton?: string | number;
    modalContainer?: string | number;
    rowItem?: string | number;
  };
  primary: {
    background: {
      normal: string;
    };
    text: {
      normal: string;
      lowContrast: string;
      ultraLowContrast: string;
    };
    ghostButtonHover: string;
  };
  secondary: {
    background: {
      normal: string;
      transparent: string;
      hover: string;
    };
  };
  success: {
    background: string;
    text: string;
  };
  warning: {
    background: string;
    text: string;
  };
  error: {
    background: string;
    text: string;
  };
};
```

To change corner roundness, set `theme.borderRadius`. There is no top-level `borderRadius` prop.

### `brandColor`

The main highlight color of the widget.

### `disableShadowDom`

Renders the widget without shadow DOM. Use it if a library doesn't support shadow DOM, or for server-side rendering. Default: `false`. Shadow DOM is on by default to avoid style conflicts.

### `rootId`

Adds a `data-root-id` attribute to every root element of the widget, including portals. Useful for `document.querySelector` or scoped styling.

```ts
rootId?: string;
```

### `modalZIndex`

`z-index` for the widget's modals.

```ts
modalZIndex?: number;
```

- **Default:** `10`

## Fees

### `chainIdsToAffiliates`

Affiliate fees per chain, and the addresses that receive them. See [Affiliate Fees](/general/affiliate-fees).

<Info>
The total `basisPointsFee` must be the same on every chain. Each address must be valid for its chain.
</Info>

```ts
chainIdsToAffiliates: {
  'noble-1': {
    affiliates: [{
      basisPointsFee: '100', // 1% fee
      address: 'noble...1', // address to receive fee
    },
    {
      basisPointsFee: '100', // 1% fee
      address: 'noble...2', // address to receive fee
    }]
  },
  'osmosis-1': {
    affiliates: [{
      basisPointsFee: '200', // 2% fee
      address: 'osmo...1', // address to receive fee
    }]
  }
}
```

## Wallets

### `connectedAddresses` and signers

If your app has already connected the user's wallets (for example MetaMask for EVM, Phantom for Solana, or Keplr for Cosmos), pass both `connectedAddresses` and the signer functions below. The widget then uses those wallets instead of asking the user to connect again. See the [example implementation](https://github.com/skip-mev/skip-go/tree/staging/examples/nextjs/src/app/injected/page.tsx).

`connectedAddresses` maps chain IDs to addresses:

```typescript
const connectedAddresses: Record<string, string> = {
  "1": "0x123...abc",          // Ethereum mainnet address
  "cosmoshub-4": "cosmos1...", // Cosmos Hub address
  "solana": "3n9...xyz",       // Solana address
};
```

Signer functions:

- **`getCosmosSigner(chainId: string): Promise<OfflineSigner>`**: Returns a Cosmos signer from [`@cosmjs`](https://docs.keplr.app/api/cosmjs.html).
- **`getEvmSigner(chainId: string): Promise<WalletClient>`**: Returns an EVM `WalletClient` from [`viem`](https://viem.sh/docs/clients/wallet.html).
- **`getSvmSigner(): Promise<Adapter>`**: Returns a Solana wallet `Adapter` from [`@solana/wallet-adapter-base`](https://solana.com/developers/cookbook/wallets/connect-wallet-react).

```jsx
<Widget
  connectedAddresses={connectedAddresses}
  getCosmosSigner={getCosmosSigner}
  getEvmSigner={getEvmSigner}
  getSvmSigner={getSvmSigner}
/>
```

### `walletConnect`

WalletConnect configuration for wallet connections.

```ts
walletConnect?: {
  options: {
    projectId?: string;
    name?: string;
  } | null;
  walletConnectModal?: {
    themeVariables?: Record<string, string>;
    themeMode?: "light" | "dark";
    privacyPolicyUrl?: string;
    termsOfServiceUrl?: string;
  } | null;
};
```

## Network

### `onlyTestnet`

Shows only testnet chains. Default: `false`.

### `apiUrl`

Overrides the default Skip proxied API endpoint. Your domain must be whitelisted; reach out on [Discord](https://discord.com/invite/interchain). You can also pass `apiKey` to send your [Skip Go API key](/general/api-keys).

### `endpointOptions`

Overrides the default Skip proxied RPC and REST endpoints. Your domain must be whitelisted; reach out on [Discord](https://discord.com/invite/interchain).

```ts
endpointOptions?: {
  endpoints?: Record<string, EndpointOptions>;
  getRpcEndpointForChain?: (chainId: string) => Promise<string>;
  getRestEndpointForChain?: (chainId: string) => Promise<string>;
};
```

### `skipExplorerUrl`

Base URL of the Skip explorer that transaction history links point to.

```ts
skipExplorerUrl?: string;
```

- **Default:** `https://explorer.skip.build`

## Events

### Callbacks

Pass these functions as top-level props to react to widget events.

| Prop | Called when | Receives |
|---|---|---|
| `onWalletConnected` | A wallet connects | `{ walletName, chainIdToAddressMap?, chainId?, address? }` |
| `onWalletDisconnected` | A wallet disconnects | `{ walletName, chainType? }` |
| `onTransactionSignRequested` | The widget asks the user to sign a transaction | `{ chainId, signerAddress?, txIndex }` |
| `onTransactionBroadcasted` | A transaction is broadcast. Called once per transaction in multi-transaction routes | `{ txHash, chainId, explorerLink, sourceAddress, destinationAddress, sourceAssetDenom, sourceAssetChainId, destAssetDenom, destAssetChainId }` |
| `onTransactionComplete` | The route completes | Same fields as `onTransactionBroadcasted` |
| `onTransactionFailed` | A transaction fails | `{ error: string }` |
| `onRouteUpdated` | The route changes | `{ srcChainId?, srcAssetDenom?, destChainId?, destAssetDenom?, amountIn?, amountOut?, requiredChainAddresses? }` |
| `onSourceAndDestinationSwapped` | The user swaps source and destination | `{ srcChainId?, srcAssetDenom?, destChainId?, destAssetDenom?, amountIn?, amountOut? }` |
| `onSourceAssetUpdated` | The source asset changes | `{ chainId?, denom? }` |
| `onDestinationAssetUpdated` | The destination asset changes | `{ chainId?, denom? }` |

## Analytics

Enables Amplitude analytics for the widget. Default: `false`.
