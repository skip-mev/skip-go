This page is for Cosmos SDK and EVM developers who are new to Solana transactions. When a route starts on an SVM chain such as Solana, the Skip Go API returns an `SvmTx` object for the user to sign. This page describes its fields and shows how to sign and execute it with `@skip-go/client`.

## `SvmTx` Fields

| Field | Description |
|---|---|
| `chain_id` | The ID of the chain to submit the transaction to (for example `solana`). |
| `tx` | The unsigned transaction, as base64-encoded bytes. |
| `signer_address` | The address that must sign the transaction, which is the user's address on this chain. |

`tx` is a complete transaction. Don't change or add anything before signing. It already includes:

* A recent blockhash, which Solana uses in place of a nonce
* The instructions (Solana's equivalent of messages)
* A priority fee. See [How Priority Fees Are Set](#how-priority-fees-are-set).

The recent blockhash expires after about a minute, so the user must sign and submit the transaction within that time. For more on Solana transactions, see [Solana's documentation](https://solana.com/docs/core/transactions).

## Execute a Solana Route with `@skip-go/client`

`executeRoute` signs `tx` with the user's wallet and submits it through the Skip Go API's `/submit` endpoint. `/submit` handles retries and multiple RPC providers, so transactions still land when Solana is congested. If you call the REST API directly, submit signed Solana transactions through `/submit` as well.

### 1. Install a Solana wallet library

We recommend [@solana/wallet-adapter](https://github.com/anza-xyz/wallet-adapter#readme). It wraps all major Solana wallets, such as Phantom and Backpack, in a standard `Adapter` object, and provides React components for choosing a wallet. See the [list of supported wallets](https://github.com/anza-xyz/wallet-adapter/blob/master/PACKAGES.md).

```shell
npm i @solana/wallet-adapter-react @skip-go/client
```

### 2. Provide the wallet adapter and execute the route

Pass a `getSvmSigner` function to `executeRoute`. It returns the `Adapter` of the wallet the user connected.

```typescript
import { useWallet } from '@solana/wallet-adapter-react';
import { executeRoute } from '@skip-go/client';

// Inside a React component
const { wallet } = useWallet();

await executeRoute({
  route,
  userAddresses,
  getSvmSigner: async () => {
    if (!wallet) throw new Error('No Solana wallet connected');
    return wallet.adapter;
  },
});
```

For how to get `route` and `userAddresses`, see [EVM Transactions](/advanced-transfer/evm-transactions).

## How Priority Fees Are Set

A Solana priority fee affects how likely a transaction is to be included in a block. Unlike on most other major networks, Solana evaluates priority fees locally: a transaction's fee is compared only with other transactions that access the same state, such as the same DEX pool or token contract.

* If the fee is low compared with those transactions, the transaction is unlikely to be included.
* If the fee is high compared with those transactions, the transaction is likely to be included.

So transactions that touch congested state cost the most.

For each transaction, Skip Go requests a recommended priority fee estimate for that transaction from its Solana RPC provider and sets the fee to match.
