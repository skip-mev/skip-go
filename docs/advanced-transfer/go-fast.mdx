Go Fast is a decentralized bridging protocol built by Skip. It moves assets from EVM chains to Cosmos in seconds instead of minutes. For example, a USDC transfer from Arbitrum to Osmosis takes about 10 seconds with Go Fast, compared with about 18 minutes over CCTP.

Go Fast trades lower fees for speed. If cost matters more than speed for your users, leave it disabled.

For the protocol design, see the [Go Fast design overview](https://github.com/skip-mev/go-fast-contracts#skip-go-fast-design-overview).

## Enable Go Fast

Go Fast is used only when you turn it on:

* **API:** Set `go_fast: true` in `/route` or `/msgs_direct`.
* **Client Library:** See [Use the Go Fast Transfer System](/client/advanced-features#use-the-go-fast-transfer-system).
* **Widget:** See [`routeConfig`](/widget/configuration#routeconfig).

Even when Go Fast is enabled, the API returns a Go Fast route only if the transfer is within the limits below.

## Supported Chains and Limits

Go Fast transfers USDC from these source chains:

| Source chain | Minimum transfer (USD) | Maximum transfer (USD) |
|---|---|---|
| Ethereum | 20 | 25,000 |
| Arbitrum | 10 | 25,000 |
| Avalanche | 10 | 25,000 |
| Base | 10 | 25,000 |
| Optimism | 10 | 25,000 |
| Polygon | 10 | 25,000 |

The destination can be any Cosmos chain that Skip Go reaches over IBC. Go Fast delivers the USDC to Osmosis, and the rest of the route continues over IBC. Go Fast doesn't support transfers between EVM chains.

If the user starts with an asset other than USDC, Skip Go first swaps it to USDC on the source chain. The limits apply to the amount after that swap.

## Fees

Solvers fill orders with their own capital and take on the risk of a reorg on the source chain. In return, the user pays a fee, which is the difference between the order's input and output amounts. The fee has three parts:

* **Transfer fee:** 10 basis points of the transfer amount, on all source chains and transfer sizes
* **Source chain fee:** a fixed amount set per source chain, to cover the solver's settlement costs
* **Destination chain fee:** a fixed amount set per destination chain

The route response shows the total in `estimated_fees` as a `BRIDGE` fee.

## How It Works

1. **Submit an order:** The user calls `submitOrder` on the Go Fast contract on the source chain, with the assets, an optional message, and the destination address. The contract emits the order as an intent.
2. **Fill the order:** Solvers, which anyone can run, watch for intents. A solver decides whether to fill an intent based on its funds on the destination chain and the fee. To fill it, the solver calls `fillOrder` on the Go Fast contract on the destination chain. This sends the assets to the user and runs any action in the message, such as a contract call. For the user, the transfer is now complete.
3. **Settle:** The solver calls `initiateSettlement` on the destination chain's Go Fast contract, listing the orders it filled. The contract sends a message to the source chain over Hyperlane.
4. **Repay the solver:** A relayer delivers the message to the source chain. The `settle` function checks each fill, then pays the solver back the assets it provided plus the fees.

If no solver fills an order in time, the user is refunded on the source chain. See [Go Fast failures](/advanced-transfer/handling-cross-chain-failure-cases#go-fast-failures).

## Run a Solver

Go Fast is permissionless, so anyone can run a solver.

* **Reference solver:** The [open-source reference solver](https://github.com/skip-mev/skip-go-fast-solver) monitors orders, fills them, settles, and rebalances funds. Configure the chains to solve for, your node endpoints, and your capital and rebalancing preferences.
* **Protocol contracts:** To build your own solver, use the open-source [Solidity and CosmWasm contracts](https://github.com/skip-mev/go-fast-contracts) directly.

If you have questions about running a solver, reach out to us on [Discord](https://discord.com/invite/interchain).
