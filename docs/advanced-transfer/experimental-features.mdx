---
title: "Experimental Features"
description: "The features you can turn on with the experimental_features parameter, and their identifiers"
---

Some newer routing features are opt-in. To use them, list their identifiers in the `experimental_features` parameter. This lets integrators adopt new features early without changing behavior for integrators who haven't opted in.

## How to Use

Pass an array of feature identifiers in `experimental_features` on `/route` and `/msgs_direct`:

```json
"experimental_features": ["eureka", "stargate", "layer_zero"]
```

In the Client Library, pass `experimentalFeatures` to `route`. In the Widget, set `routeConfig.experimentalFeatures`. The Widget enables all three features below by default.

## Available Features

| Identifier | Feature | Status |
|---|---|---|
| `eureka` | Routes over the IBC Eureka bridge between Cosmos and Ethereum | Opt-in |
| `stargate` | Routes over the Stargate V2 bridge on EVM chains, including Sei EVM | Opt-in |
| `layer_zero` | Routes that move supported OFT tokens between Initia and EVM chains over LayerZero | Opt-in |

Without the identifier in the request, routes that need the feature are not returned.
