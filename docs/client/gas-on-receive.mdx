---
title: "Gas on Receive with Custom Frontends"
description: "Give users native gas tokens on the destination chain when you build your own frontend with the Skip Go Client Library"
---

Gas on Receive splits a swap into two routes: the main route, and a small gas route that gets the user native gas tokens on the destination chain. This keeps users from ending up with assets they can't move because they have no gas.

The [Widget](/widget/gas-on-receive) does this automatically. If you build your own frontend with `@skip-go/client`, follow the steps below.

## Requirements

- `@skip-go/client` v1.5.3 or later
- Signers for every chain in the routes. See [Signer Setup](/client/getting-started#signer-setup).

Supported chains:

- **Source:** Any chain except Ethereum mainnet and Sepolia
- **Destination:** Cosmos and EVM chains. Solana isn't supported.

## How `getRouteWithGasOnReceive` Works

`getRouteWithGasOnReceive` takes a route you already requested and returns two routes:

1. It checks that the source and destination chains are supported, and that the destination asset isn't already the chain's gas token.
2. It picks the gas amount:
   - **Cosmos destination:** 3 times the chain's gas price, in each of the chain's fee tokens.
   - **EVM destination:** $2.00 worth of the source asset, swapped to the chain's native token.
3. It requests a gas route for that amount and a main route for the rest of the input.

It returns `{ mainRoute, gasRoute }`. If any step fails, or the new main route needs different chains or a different number of transactions than your original route, it returns your original route as `mainRoute` and `gasRoute` as `undefined`.

`getRouteWithGasOnReceive` doesn't check whether the user already has gas. Decide that yourself, as in step 1 below.

## Step 1: Check whether the user needs gas

Check the user's native token balance on the destination chain with `balances`. EVM native tokens use the `<chain>-native` denom, such as `arbitrum-native`.

```typescript
import { balances } from "@skip-go/client";

const result = await balances({
  chains: {
    "42161": { address: userArbitrumAddress, denoms: ["arbitrum-native"] },
  },
});
const nativeBalance = result?.chains?.["42161"]?.denoms?.["arbitrum-native"]?.amount;
const needsGas = !nativeBalance || nativeBalance === "0";
```

Let the user turn Gas on Receive on or off, and default it to on when `needsGas` is true. The Widget does the same.

## Step 2: Split the route

```typescript
import { route, getRouteWithGasOnReceive } from "@skip-go/client";

const routeRequest = {
  amountIn: "1000000", // 1 OSMO
  sourceAssetChainId: "osmosis-1",
  sourceAssetDenom: "uosmo",
  destAssetChainId: "42161", // Arbitrum
  destAssetDenom: "0x82aF49447D8a07e3bd95BD0d56f35241523fBab1", // WETH
};

const originalRoute = await route(routeRequest);
if (!originalRoute) throw new Error("No route found");

const { mainRoute, gasRoute } = await getRouteWithGasOnReceive({
  routeResponse: originalRoute,
  routeRequest,
});
```

Show the user how much gas they will receive, for example from `gasRoute.usdAmountOut`, before they confirm.

## Step 3: Execute the routes

If there is a gas route, execute both routes with `executeMultipleRoutes`. Each route needs its own user addresses, because the two routes can require different chains. Otherwise, execute the main route with `executeRoute`.

```typescript
import { executeMultipleRoutes, executeRoute } from "@skip-go/client";

const addressesFor = (chainIds: string[]) =>
  chainIds.map((chainId) => ({ chainId, address: getUserAddress(chainId) }));

if (gasRoute) {
  await executeMultipleRoutes({
    route: { mainRoute, gasRoute },
    userAddresses: {
      mainRoute: addressesFor(mainRoute.requiredChainAddresses),
      gasRoute: addressesFor(gasRoute.requiredChainAddresses),
    },
    slippageTolerancePercent: { mainRoute: "1", gasRoute: "10" },
    getCosmosSigner,
    getEvmSigner,
    onRouteStatusUpdated: (status) => {
      const gasRouteStatus = status.relatedRoutes?.find((r) => r.routeKey === "gasRoute");
      if (gasRouteStatus?.status === "failed") {
        console.warn("Gas route failed. The main swap is not affected.");
      }
    },
  });
} else {
  await executeRoute({
    route: mainRoute,
    userAddresses: addressesFor(mainRoute.requiredChainAddresses),
    getCosmosSigner,
    getEvmSigner,
  });
}
```

`getUserAddress`, `getCosmosSigner`, and `getEvmSigner` stand for your app's own address lookup and signers.

A gas route is small, so use a higher slippage tolerance for it (10% in this example) than for the main route.

## If the Gas Route Fails

The gas route runs separately from the main route. If it fails, the main swap still completes and the user doesn't receive the gas tokens. Check `relatedRoutes` in `onRouteStatusUpdated`, as in step 3, and tell the user that the gas top-up didn't arrive.
