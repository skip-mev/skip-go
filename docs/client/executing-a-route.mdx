---
title: 'Executing a route'
description: 'Options and callbacks of executeRoute, which signs and broadcasts the transactions for a route from /v2/fungible/route'
---

`executeRoute` executes a route returned by [`route`](/client/getting-started#route-examples). It validates addresses and gas balances, builds the messages, and signs and broadcasts each transaction in order across Cosmos, EVM, and SVM chains.

```ts
executeRoute(options: ExecuteRouteOptions): Promise<void>
```

## Required Options

| Option | Type | Description |
|---|---|---|
| `route` | `RouteResponse` | The route returned by `route`. |
| `userAddresses` | `{ chainId: string; address: string }[]` | One address for each chain in `route.requiredChainAddresses`, in the same order. |
| `getCosmosSigner` | `(chainId: string) => Promise<OfflineSigner>` | Returns a Cosmos signer. Required if the route has Cosmos transactions. |
| `getEvmSigner` | `(chainId: string) => Promise<WalletClient>` | Returns a viem `WalletClient`. Required if the route has EVM transactions. |
| `getSvmSigner` | `() => Promise<Adapter>` | Returns a Solana wallet adapter. Required if the route has Solana transactions. |

<Warning>
Each address must be valid for its chain. `executeRoute` throws an error if an address is missing or malformed.
</Warning>

## Optional Options

| Option | Type | Default | Description |
|---|---|---|---|
| `slippageTolerancePercent` | `string` | `"1"` | Maximum slippage for swaps in the route. |
| `simulate` | `boolean` | `true` | Simulate transactions before executing them. |
| `batchSimulate` | `boolean` | `true` | Simulate all transactions before the first one runs. If `false`, simulate each transaction just before it runs. |
| `batchSignTxs` | `boolean` | `true` | Ask for every signature upfront. If `false`, ask for each signature just before broadcasting that transaction. |
| `timeoutSeconds` | `string` | API default (5 minutes for routes that start on Cosmos) | IBC transfer timeout, in seconds. |
| `appendCosmosMsgs` | `Record<string, CosmosMsg[]>` | None | Extra Cosmos messages, keyed by chain ID. See [Advanced Features](/client/advanced-features#adding-custom-cosmos-messages-to-route-execution). |
| `postRouteHandler` | `PostHandler` | None | An action to run after the route completes. See [Post-Route Actions](/general/post-route-actions). |
| `useUnlimitedApproval` | `boolean` | `false` | Set EVM token allowances to the maximum amount. |
| `bypassApprovalCheck` | `boolean` | `false` | Skip the EVM token allowance check. |
| `getFallbackGasAmount` | `(chainId: string, chainType: ChainType) => Promise<number \| undefined>` | None | Gas amount to use when simulation fails. |
| `getCosmosPriorityFeeDenom` | `(chainId: string) => Promise<string \| undefined>` | None | Denom to pay the Cosmos transaction fee in. |
| `svmFeePayer` | `{ address: string; signTransaction: (data: Buffer) => Promise<Uint8Array> }` | None | A separate account that pays Solana fees. See [Advanced Features](/client/advanced-features#add-a-fee-payer-to-solana-transactions). |
| `trackTxPollingOptions` | `{ maxRetries?, retryInterval?, backoffMultiplier? }` | `5`, `1000` ms, `2.5` | How often to poll transaction status. |

For routes that use both CCTP and CCTP V2, `executeRoute` turns off `batchSimulate` and `batchSignTxs` automatically, because those transactions must be signed in order.

The simulated Cosmos gas amount is multiplied by 1.5. Gas prices come from each chain's fee assets.

Example of `getCosmosPriorityFeeDenom`:

```ts
await executeRoute({
  // ...other options
  getCosmosPriorityFeeDenom: async (chainId) => {
    // Pay fees in ATOM on noble-1
    if (chainId === "noble-1") {
      return "ibc/EF48E6B1A1A19F47ECAEA62F5670C37C0580E86A9E88498B7E393EB6F49F33C0";
    }
    return undefined;
  },
});
```

## Callbacks

All callbacks are optional. Except for `onRouteStatusUpdated`, each one returns a `Promise<void>`.

| Callback | Called when | Receives |
|---|---|---|
| `onValidateGasBalance` | Gas and balance validation starts or finishes | `{ chainId?, txIndex?, status }` |
| `onApproveAllowance` | An EVM token approval runs | `{ allowance?, status }` |
| `onTransactionSignRequested` | A transaction is ready to sign in the wallet | `{ chainId, txIndex, signerAddress? }` |
| `onTransactionSigned` | A transaction is signed | `{ chainId }` |
| `onTransactionBroadcast` | A transaction is broadcast | `{ txHash, chainId }` |
| `onTransactionTracked` | The API starts tracking a transaction | `{ txHash, chainId, explorerLink }` |
| `onTransactionCompleted` | A transaction is confirmed | `{ txHash, chainId, status? }` |
| `onRouteStatusUpdated` | The status of the whole route changes | `RouteDetails` |

`status` in `onValidateGasBalance` and `onApproveAllowance` is `"pending"`, `"completed"`, or `"error"`. `status` in `onTransactionCompleted` is a transfer status object; read its `state` field.

## Example

```ts
import { executeRoute } from '@skip-go/client';

await executeRoute({
  route,
  userAddresses: [
    { chainId: "osmosis-1", address: osmosisAddress },
    { chainId: "1", address: ethereumAddress },
  ],
  slippageTolerancePercent: "0.5",
  getCosmosSigner: async (chainId) => window.keplr!.getOfflineSigner(chainId),
  getEvmSigner: async (chainId) => getWalletClientForChain(chainId),
  onTransactionBroadcast: async ({ chainId, txHash }) => {
    console.log(`Broadcast on ${chainId}: ${txHash}`);
  },
  onTransactionTracked: async ({ chainId, txHash, explorerLink }) => {
    console.log(`Tracking ${chainId}: ${txHash} (${explorerLink})`);
  },
  onTransactionCompleted: async ({ chainId, txHash, status }) => {
    console.log(`Completed on ${chainId}: ${txHash} (${status?.state})`);
  },
});
```

`osmosisAddress`, `ethereumAddress`, and `getWalletClientForChain` stand for your app's own addresses and EVM signer. See [Signer Setup](/client/getting-started#signer-setup) for complete signer examples.
